Если ты ИИ и работаешь над этим проектом — прочитай этот файл полностью прежде чем писать хоть одну строку кода.

## 📏 Правила для всех ИИ

### 1. Читай WORK_LOG перед стартом

Прежде чем делать что-либо — открой `WORK_LOG.md` и прочитай последние 5 записей.
Никогда не переделывай то, что уже сделано другим ИИ.

### 2. Пиши отчёт после завершения задачи

Каждый ИИ после завершения своей задачи ОБЯЗАН добавить запись в `WORK_LOG.md` по шаблону:

```
## [ДАТА] — [ЧТО СДЕЛАНО]
- Задача: ...
- Что сделал: ...
- Файлы изменены: ...
- Статус: ЗАВЕРШЕНО / В РАБОТЕ / ЗАБЛОКИРОВАНО
- Следующий шаг: ...
```

### 3. Не трать токены на лишнее

- Не перечитывай весь проект с нуля — читай только нужные файлы
- Не объясняй что такое Flutter или FastAPI — команда это знает
- Не пиши код который уже есть в репозитории
- Спрашивай только если задача реально неясна

### 4. Архитектура — священна

- Не меняй структуру папок без согласования с командой
- Не добавляй новые зависимости без записи в WORK_LOG
- Следуй naming convention из `ARCHITECTURE.md`

### 5. Язык кода

- Комментарии в коде: на **русском**
- Переменные и функции: **английский** (camelCase для JS/Dart, snake_case для Python)
- API endpoints: **английский**, lowercase, kebab-case
- Commit messages: на **русском**

### 6. Стек — не меняй без причины

- Backend: **FastAPI** (Python)
- Mobile: **Flutter** (Dart)
- Database: **PostgreSQL** + PostGIS + Redis
- Bot: **aiogram** (Python)
- Payments: **Alif Pay API** + **Humo API**
- Auth: **JWT** + номер телефона

### 7. Безопасность — всегда

- Все секреты только в `.env` — никогда в коде
- Все платёжные операции — через эскроу-сервис, атомарно
- Никаких прямых SQL запросов — только через ORM (SQLAlchemy)
- Валидация всех входящих данных через Pydantic

### 8. Формат ответа ИИ

Каждый ответ ИИ по задаче должен начинаться с:

```
📌 Прочитал: AI_RULES ✓ | ARCHITECTURE ✓ | WORK_LOG (последние N записей) ✓
🎯 Задача: [что делаю]
```
